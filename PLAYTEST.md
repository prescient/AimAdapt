### Not working
- **Fixed:** pressing Start on a program day or workout opened a second app window instead of the game (`785f7ff`, with a regression test).
- **Fixed:** on Float Track the ball sank through the floor. Its spawn area reaches 10° below eye level, and moving targets only bounced off the spawn area, not the room. Moving targets now also bounce off the floor, ceiling and walls. Regression test: every built-in scenario, in both modes, is played for 60 s and checked every frame for targets leaving the room.
- **Switching ratings are mostly target acquisition time** (Speed Switch, Stability Switch). Why it happens in each:
  - **Stability Switch** rates tracking speed, scored as the share of each 2-second segment spent on *any* target. The time spent moving to the next target after a kill counts as off target. With a kill every ~1.5 s, a large part of every segment is travel, so the rating mostly measures how fast you get to the next target, not how steady you stay on it.
  - **Speed Switch** rates target lifetime, and each timer starts when its target appears. With four targets up at once, a target's timer runs while you're killing the others, so the rating depends on how quickly you work through the queue (and the order you pick, since there's no countdown to see). Kill time is fixed at about 0.15 s, so acquisition is the only thing being measured.
  - **Possible fixes, to decide later:**
    - Stability: score each target from first contact to its kill, as the share of that time you stay on it, so travel between targets doesn't count. The rating then reflects staying on target at speed.
    - Speed: time each target from when you start on it (after the previous kill), not from when it appears. Or keep it as acquisition but rate it directly as kill-to-kill time.
    - Report acquisition time and on-target time as separate numbers in Insights for switching scenarios.
  - **Your ideas:**
    - **Lock the target you're on.** Once you've reached a target, it changes color (e.g. turns red) until it dies, so you know to finish it before moving on. Scoring would use the same lock: time off target only counts while a target is locked, and travel to the next one doesn't count.
    - **Kills as the metric**, e.g. aiming for 45 kills in 60 seconds. The math: 45 kills a minute is one kill every 1.33 s on average. That fits the rating as a *pace*: a kill is a success if it comes within T seconds of the previous one, and your rating is the T you meet 85% of the time. Because most kills come in under T, the kill count is a bit higher than 60 ÷ T: a 1.5 s rating is roughly 45 kills a minute. The app would show both, e.g. "85% of kills within 1.5 s, about 45 kills/min".
  - **Leaning toward:** Speed Switch rated on kill-to-kill pace (the kills idea; acquisition is the skill there). Stability Switch keeps tracking speed as the difficulty, adds the lock, and scores only the time while a target is locked. Both show kills per minute too.
  - **Health bars and regeneration instead of the lock color** (your idea, replaces the red lock): each target shows a small health bar, and damaged targets heal when you're off them. You can see your progress on each one and abandon a target if you need to, at the cost of its health coming back. This needs no lock color. For scoring, a target counts as *engaged* while it's damaged and not yet healed back to full. Time on target is measured while any target is engaged. Travel to a fresh target after a kill doesn't count, but leaving a half-killed target does, until it has healed. Engine notes: `regen_per_s` already exists for beam scenarios. The bar needs drawing above each target (positioned on screen from the camera) and should be on by default for switching scenarios.
  - **Timed Grid has the same queue problem** (noted while explaining it): three targets with their own timers, each starting when the target appears, so the rating depends partly on the order you clear them. The countdown (Ideas) helps here, and so would the kill-pace rating suggested for Speed Switch.
  - **Agreed direction for Stability Switch:** keep time on target as the measure, because it matters, but only while a target is locked. Target speed is the difficulty. Adaptive mode keeps you in a band: the speed is set so your locked on-target share lands around 80–90%, the same 85% goal as other tracking. Kills per minute and acquisition time are shown alongside, not used for the rating.

### Changes made after the session
All of these have regression tests (see [TESTING.md](TESTING.md)).
- **Adapt between runs.** The first adaptive run on a drill is a calibration run that adapts as you play. Every later run plays at one difficulty, shown at the start ("This run: 0.62 s", plus "At your level", "Stretch run" or "Easy run"), and the rating updates from the whole run. Run picks follow the mix, with no stretch run after a stretch run or after a run more than 10 points below the goal. A breakthrough is holding 85% for a whole run at a value past your best. Earlier "fastest hit" values came from single targets, so they aren't used as your best; the first fixed run that holds 85% sets it.
- **Speed Switch is rated on kill pace.** Its targets no longer time out. A kill within the pace of the one before is a success; each full window with no kill is a failure, and the late kill that ends it doesn't count. The HUD shows "Next kill within …" and kills a minute. Because the knob changed, your old Speed Switch rating isn't carried over and the next adaptive run is a calibration run.
- **Stability Switch and Switch Track count engaged time only.** Targets show health bars and heal when you leave them (40/s and 60/s). Time on target only counts while some target is damaged and not yet healed, so the trip to a fresh target after a kill isn't off target, but leaving a half-killed one is, until it heals. Target speed is still the difficulty, held at 85%.
- **Timed targets show time left and alternate colors.** A bar above each timed target empties as its time runs out, and each new timed target switches between orange-red and blue. Both are scenario options (`timer_bar`, `alternate_colors`, `alt_color`), on by default.
- **Insights for switching** shows kills a minute, acquisition time (kill to reaching the next target) and on-target share while killing, as separate numbers.
- Not done yet: offering another calibration run after a long break, and kill pace for Timed Grid if the bars and colors aren't enough (both in [BACKLOG.md](BACKLOG.md)).

### Ideas and changes
- **Adapt between runs, not during them.** Changing difficulty target by target inside a run feels chaotic. Instead, each run plays at one fixed difficulty, and the rating updates once the run is over. What follows from that:
  - **The rating maths stays the same.** A full run at one speed is a lot of evidence at that point (40–80 targets, or 30 tracking segments), and the estimate absorbs it in one go.
  - **Finding your level takes a few runs instead of a few seconds.** If the first guess is far off, the first run will feel too easy or too hard, but the rating moves a long way after it because it's still uncertain. With 4–5 reps per drill in Core Week, it should settle within the first session on each drill.
  - **The near/stretch/easy mix moves to the run level.** Each run is picked as near your rating (most runs), a stretch run, or an easy one, with the same guard rails: no stretch run right after a run well below the goal, and never two in a row. Breakthroughs become "you held 85% at a speed faster than your best".
  - **The game shows the difficulty up front.** For example "This run: 0.62 s targets", with a result such as "You hit 88%; rating 0.60 s (was 0.62 s)".
  - **Decided: one calibration run at the outset.** The first adaptive run on a drill you've never played adapts during the run, as it does today, to find your level quickly. Every run after that plays at one fixed difficulty and updates the rating at the end. The game labels the first run "Calibration run" so the moving difficulty is expected. If the rating has become very uncertain (for example after a long break), one more calibration run could be offered rather than forced.
- **Alternate target colors between timeouts** (Timed Grid): each new target comes in a different color from the one before (e.g. cycling two or three colors), so it's easy to tell a fresh target with a full timer from an older one that's about to expire. This works alongside the countdown below: color shows which target is which, and the countdown shows how long each has left. Keep the colors distinct for color-blind players (e.g. orange/blue rather than red/green), and make it a scenario option that's on by default for timed scenarios.
- **Done:** **Visible countdown on timed targets (priority, after this session).** On Speed Switch, four targets are up at once, each with its own timer. Nothing shows how much time a target has left, so you can't tell which one to take first. Show the remaining time, for example by shrinking the target slightly or fading its color as the timer runs out. This applies to every timed scenario. Done as a time-left bar above each target.
